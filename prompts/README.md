# 提示词目录与维护约定

本目录集中保存模型提示词，一个消息用途对应一份UTF-8 Markdown文件。修改规则、措辞、示例时编辑文件，消息角色、数据插入、模型选择、异常处理和流程控制仍由代码负责。

## 目录与变量

| 文件 | 用途 | 必需变量 |
|---|---|---|
| `generation/knowledge_answer.md` | 知识库回答系统规则 | 无 |
| `generation/knowledge_question.md` | 本次证据与问题的用户消息 | `context`、`input` |
| `parsing/page_review.md` | 精确异常页面或区域的视觉复查 | `target_id`、`document_format`、`locator`、`anomaly_names`、`evidence` |
| `memory/conversation_summary.md` | 会话增量摘要 | `existing_summary`、`transcript` |

知识库系统规则和用户消息分成两个文件，是为了保留系统指令与文档资料的权限边界。会话历史的角色与插入位置不交给模板编辑者随意拼接。

## 如何修改

1. 找到对应文件，直接编辑中文正文。Markdown标题用于组织实际指令，代码围栏可用于标明示例；这些内容都会成为模型输入，不要混入仅给维护者看的说明。回答规则只保留 `generation/knowledge_answer.md` 一份，历史正文从 Git 或评测快照追溯。
2. 变量写为`${variable}`。新增、删除或改名时，必须同时更新调用代码的变量契约，否则直接报错。
3. JSON示例使用正常的单层花括号，无需写成Python的双花括号。字面美元符号使用`$$`。
4. 保持UTF-8编码。仅规范化文件末尾换行，不删掉正文中的空格、换行或JSON缩进。
5. 修改后重启应用或评测进程。首次加载后进程内缓存，不做热更新，避免同一轮运行中途换规则。
6. 运行自动测试，再做受影响任务的真实样例评测。提示词变化并不等于质量提升。

代码只进行一次变量替换。原文中的`${...}`、JSON花括号和模板语句不会被再次当作变量或代码执行；但这不等于已经解决模型层面的提示注入风险。

## 实现位置

- `core/prompt_loader.py`：限制目录、读取文件、校验变量和缓存模板。文件不存在、为空、编码错误、变量不匹配或路径越界时明确报错，不静默回退旧提示词。
- `generation/prompts.py`：把回答文件组装为系统消息、历史消息、用户消息，保留薄接口；提供`answer_prompt_sha256()`记录系统规则和用户模板共同构成的版本。
- `ingestion/parsers/qwen_fallback.py`：保留原`build_review_prompt()`接口，仅把正文移出代码，原有精确异常定位和模型调用不变。
- `memory/history_store.py`：保留原`_build_summary_prompt()`接口和旧摘要的字面`\n`换行行为，本次不改压缩策略。

回答模板的版本哈希应与模型、检索候选和题目版本一起进入评测缓存身份。哈希基于进程实际加载的文本，不根据文件名或修改时间猜测版本。系统规则或用户模板任意一项改变，版本哈希都会变化。

“没有资料”等程序固定提示不属于发给模型的任务模板，仍由对应业务模块管理。未来增加查询改写等模型任务时，再新增对应文件，不预先建立空模板。

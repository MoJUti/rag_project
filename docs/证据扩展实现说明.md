# 证据扩展实现说明

日期：2026-10-14；属于节点6的证据组织环节。

## 做什么，以及何时使用

召回、融合、可选重排完成后，先保留前6个命中切块，再补充同一文档的相邻内容。例如命中了说明中的一段，可以补上前面的定义或后面的条件。扩展不会重新嵌入、调用模型或改写原文。

代码位于 `retrieval/evidence_expansion.py`。问答仍使用统一的 `RetrievalPipeline`，后续预览界面会使用相同路径。

## 核心实现

1. 从 `chunks.jsonl` 文件行序建立文档内切块顺序；稳定ID是哈希，不能按ID推断相邻关系。
2. 原命中块优先保留、去重；按命中排名和距离尝试追加前后邻居。
3. 只追加同文档、同章节的内容；扩大半径时也不跨越中间的其他章节。相邻的两个结构化表格必须属于同一个原始表格元素。
4. 每块追加前计算估算Token，超预算则跳过并尝试其他候选。原命中块不占新增预算，也不会被扩展挤掉。
5. 新块保留自己的切块ID、章节、原始行/页/幻灯片/工作表定位和元素ID，只继承文档级来源信息。`expanded_from_chunk_id`说明从哪个命中块扩展，阶段追踪的 `added_chunk_ids`列出追加块。
6. 启用时完整校验邻接表与当前向量库的切块集合、文档ID和文本；每次命中也核对文本。避免旧目录把已删除内容重新补进答案。文档或索引更新后需同步目录并重启；当前尚无跨进程实时失效通知。

此实现为相邻块扩展，尚未实现父块、整章节摘要或图谱扩展。空章节路径仅表明没有章节标注，无法证明邻居在语义上相关，是否值得扩展需用实际题目验证。

## 配置

以下是可选的实验配置，修改本地 `.env` 后重启应用：

```dotenv
EVIDENCE_EXPANSION=neighbors
EVIDENCE_CHUNKS_DIRECTORY=storage/evaluations/zh_public_minibench_v0.1/chunks/structure_aware_v1
EVIDENCE_NEIGHBOR_RADIUS=1
EVIDENCE_EXTRA_TOKENS=2000
```

默认 `EVIDENCE_EXPANSION=none`。半径1表示每个命中块最多尝试前后各一块；2000是所有追加块共同使用的预算，不是每块预算。它不限制原6个命中块、会话历史及回答提示词的总Token，整个生成窗口预算需在后续节点处理。

Token采用现有切块计数器的 `cl100k_base` 估算；计数器不可用时沿用其字符估算回退，不能视为千问实际Token或计费数据。界面应标注“估算Token”。

## 复用已有题目的对照

运行 `scripts/evaluate_evidence_expansion.py`，使用固定缓存排名，没有新增题目、向量或API请求。旧55题在同来源的拼接上下文上以引文字符覆盖计算证据完整性，允许证据跨块；此口径与之前逐块判断不同，不能直接与旧报告的Recall@6相减。

下表是旧55题的完整证据命中率及平均追加Token，同一轮采用同一个评分方法：

| 原召回方式 | 只用前6块 | 追加邻居 | 继续取排名候选 | 邻居平均追加Token |
|---|---:|---:|---:|---:|
| 向量 | 76.36% | 76.36% | 80.00% | 1035 |
| 原字符BM25 | 58.18% | 63.64% | 61.82% | 1470 |
| 原字符BM25与向量融合 | 72.73% | 74.55% | 78.18% | 1319 |

两个追加方案均限制新增估算Token不超过2000，但实际消耗不同。继续取排名候选使用旧报告缓存的前10名，最多新增4块；不能据此代表更大候选池的完整效果。新增19题普通召回只缓存前6名，不能做这个对照；千问重排缓存有完整排序池，可以比较。新增19题上，邻接扩展没有增加证据命中，但增加了约1046至1359估算Token（视召回方式而定）。

当前证据支持将邻接扩展保留为可选能力，默认关闭。它可能补全缺上下文的段落，也可能追加不相关内容；本轮还没有测生成答案是否更准确。

本地机器报告：`storage/evaluations/zh_public_minibench_v0.1/reports/node6_evidence_expansion_report.json`，记录逐题追加块、证据指标和预算。该运行文件不提交Git。

# 存储目录约定

## 1. 目标

解析结果是后续切块、召回和评测的正式输入，不能与临时日志混放。项目从现在起固定区分三类目录：

```text
data/eval/     固定评测集的原始输入与人工标注
storage/       正式知识库数据和可复用评测工件
logs/          单次运行日志、调试信息和可删除的中间结果
```

## 2. 正式知识库

```text
storage/
├─ sources/<document_id>/原始文件
├─ parsed/<document_id>/parsed_document.json
├─ assets/<document_id>/mineru/ 与 review_targets/
├─ chunks/<document_id>/chunks.jsonl
└─ indexes/
```

`ParserExecutionService.parse_paths()` 会自动复制原始文件、保存统一 JSON，并将 `source_uri` 改为持久化后的源文件路径。JSON 使用同目录临时文件加原子替换，避免进程中断留下半个文件。

根目录由 `.env` 中的 `RAG_STORAGE_ROOT` 控制，默认值为项目根目录下的 `storage`。

## 3. 评测工件

```text
storage/evaluations/<dataset_id>/
├─ parsed/<document_id>/parsed_document.json
├─ assets/<document_id>/
├─ chunks/<strategy>/<document_id>/chunks.jsonl
└─ reports/
```

当前节点 3 的最终评测工件已经从实验日志提升到：

```text
storage/evaluations/zh_public_minibench_v0.1/
```

节点 4 应读取这里的 `parsed`，并把不同切块策略写入 `chunks/<strategy>/`。这样可以反复比较切块方案，而不需要重新调用 MinerU 或千问。

## 4. logs 的职责

`logs` 只保存批次轮询记录、请求诊断、阶段性报告和失败现场。删除 `logs` 不应破坏正式知识库或已经确认的评测基线。

`logs/node3_final_v9` 仍作为节点 3 的原始实验快照保留，但后续节点使用 `storage/evaluations/zh_public_minibench_v0.1`，不再依赖该日志目录。

## 5. Git 与生产环境

运行数据默认不提交 Git，只提交目录说明和占位文件。生产环境可以把 `KnowledgeBaseStorage` 替换为对象存储或数据库实现，只要继续输出相同的统一文档协议，切块与检索层无需感知底层变化。

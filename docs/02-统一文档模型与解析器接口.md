# 节点 2：统一文档模型与解析器接口

## 1. 节点目标

本节点建立多格式文档进入知识库时的稳定边界。它位于“文件上传”与“解析质量检测、切块”之间：

```text
原始文件
  → 格式识别与解析路由
  → 具体解析器（本地文本 / MinerU 文档 / MinerU HTML）
  → 统一文档模型
  → 解析质量门控（节点 3）
  → 结构化切块（节点 4）
```

本节点不执行真实批量解析，也不写入 Chroma。它只固定数据协议、解析器接口、路由规则和 MinerU API 的请求契约，避免后续组件直接依赖某个供应商的 JSON。

## 2. 为什么不能直接使用 MinerU JSON

MinerU 负责把复杂文件转换成结构化内容，但知识库仍需拥有自己的内部协议：

- MinerU 的输出字段可能随版本变化；
- 精准 API、轻量 API和本地部署暴露的产物并不完全相同；
- HTML 的结果与 PDF、Office 文档不同；
- 后续可能对比 `pipeline`、`vlm`、本地 MinerU 或其他解析器；
- 切块、引用、评测需要稳定的 `document_id` 与 `element_id`；
- 解析质量、错误、重试和人工修正记录属于知识库自身。

因此采用适配器结构：

```text
MinerU ZIP / 本地文本
          ↓
      解析适配器
          ↓
ParsedDocument v1（稳定协议）
```

## 3. 统一文档模型

核心文件：`ingestion/document_model.py`。

### 3.1 SourceDocument

记录不可变的原文件身份：

- 文件名、格式、MIME；
- 文件大小；
- SHA-256；
- 基于 SHA-256 生成的稳定 `document_id`；
- 可选来源 URI。

同一文件重复上传时会得到相同的 `document_id`。这里不再使用 Python `hash()`，因为它在不同进程之间不稳定。

### 3.2 DocumentElement

文档被表示为按阅读顺序排列的语义元素，例如：

- 标题、各级标题、段落；
- 列表和列表项；
- 表格；
- 图片、公式、代码、引用；
- 页眉、页脚和分页符。

元素使用扁平列表存储，通过 `parent_id` 和 `child_ids` 表达层级。扁平结构便于建立索引、映射评测证据和序列化；父子引用保留文档结构。

### 3.3 SourceLocation

所有位置编号面向使用者时从 1 开始，支持：

- PDF 页码和页面坐标；
- PPT 幻灯片编号；
- Excel 工作表、单元格范围和行号；
- Word 段落与表格编号；
- Markdown 行号；
- MinerU 原始定位符。

这层位置是后续将评测集证据映射为 `element_id` 和 `chunk_id` 的基础。

### 3.4 TableData

表格不是只保存为一段 Markdown，而是保留：

- 行列数；
- 单元格坐标；
- 行合并、列合并；
- 表头标记；
- 展示文本、原始值和公式。

这样才能在后续测试跨行表头、合并单元格、数值问答和 Excel 公式。

### 3.5 ParserProvenance 与 ParseIssue

每次解析记录：

- 解析器与模型版本；
- 不包含密钥的配置指纹；
- MinerU task/batch ID；
- 开始和完成时间；
- 可重试错误、警告及其原始位置。

解析结果明确区分 `success`、`partial` 和 `failed`，禁止失败结果伪装成成功文档。

### 3.6 ParseQuality

统一模型预留质量指标和总分，但本节点不定义评分算法。节点 3 会实现文字完整性、结构、表格、位置和 OCR 等质量门控。

## 4. 稳定 ID

```text
document_id = "doc_" + SHA256(原始文件字节)
element_id  = UUIDv5(document_id + 元素类型 + 阅读顺序 + 原始定位符)
```

ID 生成是确定性的：同一文件、同一元素定位和同一转换规则会产生相同 ID。后续切块 ID 也会建立在这些稳定元素 ID 上。

## 5. 解析器接口

核心文件：`ingestion/parsers/base.py`。

所有解析器统一实现：

```python
class DocumentParser(Protocol):
    @property
    def capabilities(self) -> ParserCapabilities: ...

    def probe(self, source_path: Path) -> ProbeResult: ...

    async def parse(self, request: ParseRequest) -> ParsedDocument: ...
```

`parse` 使用异步接口，因为 MinerU 是异步远程任务；本地解析器也能在统一调度器下运行。

## 6. 自动路由与模型选择

核心文件：`ingestion/parsers/routing.py`。

| 输入 | 路由 | 模型 |
|---|---|---|
| TXT、Markdown | `local_text` | 无 |
| HTML、HTM | `mineru_html` | `MinerU-HTML` |
| PDF、图片、Word、PPT、Excel | `mineru_document` | 默认 `vlm` |

HTML 与普通文档必须分批，因为 MinerU 的 `model_version` 是批次级参数。批处理器按 `(route, model_version)` 自动分组，并强制每批不超过 50 个文件。

第一版根据扩展名识别候选格式；节点 3 接入上传流程时还会检查文件签名和 MIME，防止仅修改扩展名绕过校验。

## 7. MinerU 配置

核心文件：`ingestion/parsers/mineru_contracts.py`。

使用 MinerU v4 精准解析 API：

```env
MINERU_API_TOKEN=
MINERU_API_BASE_URL=https://mineru.net/api/v4
MINERU_DEFAULT_MODEL=vlm
MINERU_HTML_MODEL=MinerU-HTML
MINERU_LANGUAGE=ch
MINERU_ENABLE_TABLE=true
MINERU_ENABLE_FORMULA=true
MINERU_MAX_BATCH_SIZE=50
```

Token 使用 Pydantic `SecretStr`，日志和对象表示不会显示明文。真实值只存于被 Git 忽略的 `.env`，`.env.example` 保持为空。

### 7.1 千问多模态异常页复核

MinerU 出现关键数字缺失、图表仅保留图片引用或跨页正文断裂时，异常页将渲染为高清图片并通过百炼 OpenAI 兼容接口交给千问复核：

```env
DASHSCOPE_BASE_URL=https://maas.qianwenaiapi.com/compatible-mode/v1
QWEN_VL_MODEL=qwen3.8-max
QWEN_VL_ENABLE_THINKING=false
```

`enable_thinking=false` 是结构化文档提取的强制参数，而不是仅依赖环境变量的建议值。调用客户端必须显式发送该参数，并对返回 JSON、数值单位、页码和原文证据进行校验。真实 API Key 仍只保存在本地 `.env`。

## 8. 校验规则

统一模型在写入磁盘前自动校验：

- 元素 ID 和资源 ID 不能重复；
- 父元素、子元素和资源引用必须存在；
- 成功状态必须至少包含一个元素；
- 表格单元格不能越界；
- 只有表格元素能携带结构化表格；
- MinerU Token 不能为空；
- HTML 与普通文件不能进入同一模型批次；
- MinerU 单批最多 50 个文件。

运行：

```powershell
.\.venv\Scripts\python.exe -m unittest test.test_document_model test.test_parser_routing -v
```

测试覆盖：

- 稳定文档与元素 ID；
- 配置指纹稳定性；
- 非法父子引用；
- 空成功文档；
- 文件格式识别；
- HTML 独立路由；
- 51 个文件自动拆为 50 + 1；
- MinerU Token 不出现在配置对象的日志表示中。

本机真实配置另行执行只返回状态的检查，不纳入可移植单元测试，避免 CI 依赖开发者的 `.env`。

# 检索策略扩展计划

更新日期：2026-10-14。

## 目标

把检索组成可替换、可单独评测的阶段，允许用户查看候选和证据，再选择适合自己资料的预设。默认方案由质量、延迟、费用共同决定，当前55题的成绩仅代表这份小型中文资料集。

## 当前落地范围

检索入口为 `retrieval/pipeline.py`，问答服务与后续预览共用 `RagService.retrieve_with_trace()`。

```text
用户问题 → 查询处理 → 一路或多路候选召回 → 融合去重
        → 可选重排 → 最终数量截断 → 证据扩展 → 回答模型
```

| 阶段 | 当前可用 | 新插件接入方式 |
|---|---|---|
| 查询处理 | 原问题 | 注入 `query_transform`，返回问题列表；默认最多4个子问题 |
| 候选召回 | 向量、BM25、两者RRF融合 | 实现 `get_candidates(query, limit)`，返回原始文档及来源元数据 |
| 中文词法 | 单字、汉字单双字与英文数字整体 | 在 `TOKENIZERS` 注册函数，正式检索与实验共用 |
| 多查询融合 | RRF | 注入 `fusion`，输入多份排名列表，输出去重候选 |
| 重排 | 关闭、千问3.7文本重排 | 在 `RERANKER_FACTORIES` 注册实现，返回原候选下标、用量和请求ID |
| 证据扩展 | 原命中块、同章节邻接块 | 注入 `evidence_expander`；邻接实现保留来源并限制新增预算，父块扩展待做 |

查询处理当前只有原问题实现；证据扩展已实现可选邻接块，结果见[证据扩展实现说明](证据扩展实现说明.md)。接口存在不代表其他具体算法已实现。解析器、切块器和向量数据库保留已有独立接口；还未合成全流程统一插件注册中心。

每次运行返回阶段耗时、问题列表、候选/排序后切块ID，模型阶段记录Token和请求ID。记录属于单次请求，避免多个会话共享“上次检索结果”。后续界面可将 `trace` 的数据类转为JSON；当前没有自动持久化这些追踪记录。

## 逐项扩展顺序与验收

| 顺序 | 能力 | 如何验证 | 额外准备 |
|---|---|---|---|
| 1 | 新增盲测题、失败案例分析 | 未参与调参的中文题；测找证据与最终答案 | 现有53份文档只有34份有本轮检索题，先补覆盖与无答案题 |
| 2 | 查询改写、问题拆解 | 同义表达、指代、跨文档组合；检查改写是否改变原意 | 讨论具体模型、调用预算；保存原问题和子问题 |
| 3 | 父块/邻接块扩展 | 正确块命中后是否缺上下文；扩展的新增Token与引用准确率 | 建立父子关系、稳定块ID、严格上下文预算 |
| 4 | 文档/时间等过滤与表格结构化检索 | 同名文档不同年份、精确数值、合计与比较 | 统一元数据字段；结构化表格与只读计算接口 |
| 5 | 上下文增强检索 | 标题、单位和指代缺失时是否改善召回 | 对新增上下文溯源审核，重新向量化和建词法索引 |
| 6 | 神经稀疏检索、Late Interaction | 同候选预算下比较中文证据召回、内存和延迟 | 确认中文模型、硬件及索引；保留原索引做对照 |
| 7 | GraphRAG、层级摘要检索 | 实体关系、多跳证据、全文/全库主题归纳 | 新建图谱或摘要索引；针对关系和归纳题单独评测 |
| 8 | 多模态检索与重排 | 图表、图片、页面布局题，比较仅OCR与图文共同检索 | 原页图像、页码区域映射、多模态嵌入及模型费用 |
| 9 | 根据资料推荐预设 | 新用户资料上的独立验收，推荐解释与手动覆盖 | 文档特征画像、小样本评测、记录策略版本和置信度 |

顺序允许按实际失败案例调整。不同技术有各自适合的题型，不能仅凭“发布较新”选择默认。自动推荐第一版应推荐候选预设，并明确依据；没有用户资料上的评测结果时，不能宣称已找到最优配置。

## 界面计划

节点9提供预设和高级设置，展示原问题/子问题、各路候选、融合和重排名次变化、最终证据来源、耗时及Token。切块预览显示边界和Token预算，预览与正式索引使用同一配置。需要独立索引的策略显示准备状态，避免用户选择未就绪策略后仍悄悄使用旧索引。

当前已进入节点7的答案、引用与拒答评测。旧刑法专用提示词已改为通用知识库规则，并接入来源编号和流式来源展示；旧主回答模型在当前平台不可用，替换及真实回答验证待确认。此阶段状态见[节点7说明](07-生成引用与拒答评测.md)。

# 节点7端到端首轮结果

日期：2026-10-15。结论：当前配置完成78道真实问答，链路可运行，但存在漏召回、证据不全、无依据补答和引用格式问题，节点7尚不能验收。

## 本轮做了什么

使用唯一的Markdown回答规则，让55道原检索题＋23道新增题进入正式RAG链。当前配置为Chroma、2048维缓存问题向量、向量与字符级BM25融合、最终6块证据、无重排/邻接扩展；千问 `qwen3.8-max` 关闭思考。每题独立历史，本轮禁用模型备用，不更改应用备用配置。

没有固定旧召回结果，没有注入标准答案，没有修改提示词或边测边调参，也没有在失败后偷偷补目标文档。实现原理、启动命令和指标边界见[端到端评测说明](节点7端到端评测说明.md)。

## 召回指标：保留原口径，不能等同答对比例

| 指标 | 原55题 | 新增19道可答题 |
|---|---:|---:|
| 文档Recall@6（逐题平均） | 95.45% | 94.74% |
| MRR@6 | 0.9364 | 0.9035 |
| 证据片段Recall@6（逐题平均） | 69.70% | 94.74% |
| 全部标注片段命中题数 | 37/55（67.27%） | 17/19（89.47%） |

**两套证据指标计算方法不同，不合并。67.27%是旧片段匹配算法的成绩，不能解释成另外18题都没有回答依据。**

本轮实际暴露出旧证据标注粒度的问题：部分标注引用的是较长段落，而模型只需其中一个短事实；解析后的格式、表格排列也与旧quote不同。例如 `wb-192-01-01` 的营业收入回答包含标准值，引用的S6也直接写明该收入，旧算法却判定证据未命中。该题不是漏召回，而是文本匹配代理指标的假阴性。

因此，95%左右的文档Recall既不能证明回答准确，67%左右的完整片段匹配率也不能直接证明三分之一的题漏证据。需要将“回答所需最小证据”与“标注长片段匹配”分开核查。暂不为了数字好看调整阈值，也不覆盖旧评分结果。

## 数据与标注本身也要复核

`ret-te-1325-01` 问“持股比例为何远高于其他人”，参考答案是“认购的股份数额最大”。模型给了表中比例，却把“为何”理解为业务背景原因而拒绝推测。这里需要区分表内数值关系与表外因果解释，不能仅按参考答案字符串判定模型错误。表内“认购股份数”字段却使用“万元”，也应保留原始不一致，不擅自改成万股。

本轮没有修改标准答案、提问、证据阈值或语料。这些都是后续评测集维护的明确候选项，修改时应保留版本和原始证据。

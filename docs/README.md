## 当前执行顺序

1. 节点7本轮按用户决定收尾：默认10块、保留流式回答；表格误读等风险登记后续优化，不实现草稿校验，不继续扩大检索调参。
2. 节点8：实现并验证记忆和会话压缩，覆盖多轮指代、关键事实保持、更新/删除、不同会话隔离与Token预算。具体策略和模型在执行前讨论，不沿用旧代码就视作已完成。
3. 节点9：把已有后端流程接入界面，展示解析质量、切块边界、各路召回、融合与重排变化、证据来源及耗时/用量；用户可选择已就绪策略。需要独立索引的策略必须显示准备状态。
4. 界面完成后做整条流程验收，并按原约定复测Chroma/Qdrant。默认仍用Chroma，Qdrant和旧1024维数据保留；复测不代表预先决定换库。
5. 自动推荐预设、GraphRAG、多模态检索等属于后续增强计划，不全部作为当前节点7至9的必做条件；自动推荐不能在没有用户资料上的验证时声称最优。

前端切块预览保留在节点9：用户可查看边界、来源、Token数，并可选择策略、目标Token、最大Token、重叠量和表格行数；预览与正式入库必须使用同一套后端配置与版本标识。

节点 4 先交付可配置的后端接口和机器可读评测结果，不在本节点提前修改 Streamlit，避免界面工作干扰切块与数据库实验。

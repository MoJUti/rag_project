# 节点 1：中文多格式 RAG 评测集

## 1. 节点目标

在更换解析器、切块方式、向量数据库或召回算法前，先建立固定且可追溯的中文评测基线。没有基线时，“效果变好”只能依靠主观体验，无法判断改动究竟提升了什么。

评测集位于：

```text
data/eval/zh_public_minibench_v0.1/
```

## 2. 文档组成

共整理 55 份中文公开测试文档：

| 格式 | 数量 |
|---|---:|
| DOCX | 6 |
| PPTX | 4 |
| XLSX | 7 |
| PDF | 2 |
| PNG | 10 |
| JPG | 2 |
| Markdown 表格 | 24 |

数据来自锁定版本的 Workspace-Bench-Lite、TableEval 和 OmniDocBench。上游版本记录在 `sources.lock.json`，文档清单记录在 `manifest.jsonl`，从而保证后续能够复现同一批资料。

## 3. 评测套件

### 3.1 正式检索集

`annotations/retrieval_questions.jsonl` 包含 55 个问题，`questions.jsonl` 是完全一致的兼容入口。

每条记录至少包含：

- 自然语言问题；
- 标准答案；
- 相关文档 ID；
- 可验证的证据位置；
- 难度、模态和数据划分；
- 必要时的多文档相关性。

其中 34 份文档承担正例，其余文档作为干扰项。问题划分为 dev、holdout-public 和 smoke，避免调参时直接污染全部测试结果。

### 3.2 表格问答集

`annotations/table_qa_cases.jsonl` 包含 26 个表格问答案例，包括多轮问题及其独立查询改写。该集合默认假设来源表格已经选定，不参与全库召回率计算。

### 3.3 解析质量集

`annotations/parser_cases.jsonl` 包含 12 个复杂页面，用于测试 OCR、版面、阅读顺序、表格和公式恢复质量。

### 3.4 拒答集

`annotations/refusal_cases.jsonl` 包含 4 个资料中无法回答的问题，用于测试系统是否会在证据不足时编造答案。

### 3.5 排除集

`annotations/excluded_cases.jsonl` 记录 13 个被排除的候选问题及原因，包括常识题、低价值题、视觉指代不完整问题和丢失合并单元格信息的问题。排除记录保留，避免后续重复引入同类错误。

## 4. 构建流程

```text
锁定公开数据版本
  → 筛选中文多格式文档
  → 提取带位置的内容块
  → 生成候选问题
  → 回查原文证据
  → 修正答案与相关文档
  → 划分正式套件
  → 自动完整性审计
```

相关脚本：

- `scripts/curate_zh_public_minibench.py`
- `scripts/extract_eval_blocks.py`
- `scripts/build_eval_questions.py`
- `scripts/build_verified_eval.py`

## 5. 证据设计

证据不是仅保存一段文本，而是同时记录可回到源文件的位置，例如 PDF 页码、PPT 页、Excel 工作表和单元格、Word 段落或表格行、Markdown 行号。

当前证据停留在“原始文档位置”层。节点 4 完成切块后会执行：

```text
证据位置 → element_id → chunk_id
```

由此计算 Recall@K、MRR、nDCG 等检索指标，并检查召回结果是否真正覆盖标准证据。

## 6. 已修正的上游问题

人工复核发现并修正了若干原始答案或提问问题，包括硬件算力差值、PMI 单位、现金管理产品遗漏，以及“是否全部赎回”的错误判断。修正记录同时保留上游答案和修改说明，详见：

- `annotations/questions_review.md`
- `annotations/audit_report.md`

## 7. 自动审计

当前自动检查覆盖：

- ID 唯一；
- 问题、答案、相关文档和证据非空；
- 所有证据块真实存在；
- 每个相关文档都有证据；
- 数据划分无泄漏；
- 正式检索集两个入口字节一致；
- 表格、解析和拒答套件结构有效。

## 8. 已知限制

- 使用公开数据，不能完全排除模型预训练污染；
- 当前主要由一次人工复核完成，不等价于双人独立标注；
- HTML 尚未包含在 v0.1 文档集中，将在解析节点加入专项测试样本；
- 最终 chunk 级真值必须等切块规则确定后才能生成。

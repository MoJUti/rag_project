# 节点 3：多格式解析、精确异常复核与质量门控

> 当前状态：实现、真实数据回归和人工确认均已完成，31 份文档全部通过质量门控，可以进入切块节点。

## 1. 节点目标

本节点把节点 2 定义的统一文档模型变成可执行的解析流水线：

```text
原始文件
  → 格式路由
  → 本地解析或 MinerU 远程解析
  → MinerU 产物适配
  → 原生格式独立校验
  → 按页/幻灯片/工作表/区域生成 ReviewTarget
  → 可确定问题由原生结构修复
  → 只有必须看图的目标调用 qwen3.8-max
  → 再次质量门控
```

本节点仍然不执行切块、不生成向量，也不写入 Chroma。只有通过质量门控的统一文档才能进入下一节点。

## 2. 已实现内容

### 2.1 本地 TXT 与 Markdown 解析

核心文件：`ingestion/parsers/local_text.py`。

- 支持 UTF-8、UTF-8 BOM 和 GB18030 回退；
- Markdown 保留标题级别、段落、列表、引用和代码块；
- 每个元素保留原始行号；
- 文档 ID 和元素 ID 可重复生成且保持稳定；
- 空文档直接判定为 `failed`。

### 2.2 MinerU v4 API 客户端

核心文件：`ingestion/parsers/mineru_client.py`。

客户端完成批次创建、签名 URL 上传、结果轮询、ZIP 下载和安全解压。ZIP 解压拒绝绝对路径、路径穿越、符号链接、异常条目数和超过 2 GB 的结果。Token 使用 `SecretStr`，请求和日志不输出明文。

### 2.3 MinerU 结果适配

核心文件：`ingestion/parsers/mineru_adapter.py` 和 `html_table.py`。

适配器读取 `content_list.json`，转换标题、正文、列表、结构化表格、图片、图表、公式、页眉和页脚。每个元素保留页面或幻灯片编号、边界框、表格行列跨度、图片 SHA-256、模型版本、批次 ID 和原始产物路径。

如果缺少 `content_list.json`，可以降级使用 `full.md`，但状态为 `partial`，不会伪装成完整解析。

### 2.4 原生格式独立校验

核心文件：`ingestion/parsers/native_extractors.py`。

| 格式 | 原生校验工具 | 校验内容 |
|---|---|---|
| PDF | pypdf | 页数、原生文字层、数字 |
| DOCX | python-docx | 段落、表格、数字 |
| PPTX | python-pptx | 幻灯片、文本框、表格、数字 |
| XLSX | openpyxl | 工作表、显示值、公式、合并区域 |

原生解析不是最终正文来源，而是独立参照。MinerU 即使返回 `done`，只要关键内容与原文件不一致，质量门控仍能发现。

### 2.5 质量门控

核心文件：`ingestion/parsers/quality_gate.py`。

当前指标包括非空内容、PDF 页覆盖、PPTX 幻灯片覆盖、原生数字召回，以及解析问题严重程度。

- `success`：结构完整，当前规则未发现缺失；
- `partial`：内容可用，但存在数字、页面或结构异常；
- `failed`：没有有效元素或关键结构不完整。

数字比较会归一化千分位、百分号、尾随零和小数点附近空格。该指标故意偏向高召回，用于发现风险，不等同于最终语义准确率。

### 2.6 精确异常模型与千问 3.8 多模态复核

核心文件：`ingestion/parsers/review_models.py`、`anomaly_detector.py`、`qwen_vision.py` 和 `qwen_fallback.py`。

固定配置：

```env
DASHSCOPE_BASE_URL=https://maas.qianwenaiapi.com/compatible-mode/v1
QWEN_VL_MODEL=qwen3.8-max
QWEN_VL_ENABLE_THINKING=false
```

代码层显式发送 `enable_thinking=false`；即使环境变量误设为 `true`，配置模型也会拒绝启动。

异常检测器把问题定位到具体页面、幻灯片、工作表或图表区域，并记录异常类型、证据和是否需要视觉模型。它覆盖空单元、低文字覆盖、缺失文字、缺失数字、表格/公式结构、视觉语义和阅读顺序，不再把整份 PDF 或正常页面批量交给千问。

复核提示词要求提取标题、段落、列表、表格、图表、公式、页眉页脚、阅读顺序和图文关系，而不只是数字。对缺失数字，程序先用 PDF 文字层定位数字及左右语境，再只渲染相关横向区域；对无可检索语义的图表，使用对应图表资产。模型输出还必须通过异常级验证规则，不能仅因返回 JSON 就自动算作解决。

千问不会无条件覆盖 MinerU 内容，只添加与目标异常对应且经过验证的证据；不确定项会被保留，不允许模型猜测。

## 3. 真实数据回归结果

对评测集中的 31 份非 Markdown 文档运行完整检测。最终处理了 56 个确定性目标和 9 个视觉目标：

| 类型 | 数量 | 处理方式 | 当前结果 |
|---|---:|---|---|
| 视觉目标 | 9 | 精确裁剪后调用千问 | 9 个已解决 |
| PDF 文字/数字缺口 | 46 | 原生 PDF 文字层补回 | 46 个已修复 |
| DOCX 文字差异 | 2 | 原生段落和表格行补回 | 2 个已修复 |
| PPTX 文字差异 | 3 | 原生幻灯片结构补回 | 3 个已修复 |
| XLSX 公式/内容结构 | 5 | 工作表级结构化表格写回 | 5 个已修复 |

千问实际收到的只有 9 个存在明确问题的目标：宏海科技年报第 86、122 页的缺失数字和第 12 页图表；太湖远大年报第 35、36、138 页的缺失数字，以及第 20 页两个图表和第 21 页一个图表。9 个目标全部解决，未解决视觉目标为 0。

确定性修复共新增 127 个文档元素：46 个 PDF 页级补充、72 个 DOCX 段落或表格行、4 个 PPTX 文本元素和 5 个 XLSX 工作表级表格。Excel 的 41,428 个公式保存在表格单元格的 `formula` 字段中，没有生成 41,428 个独立文档元素。

最终门控结果为 31 个 `success`、0 个 `partial`、0 个 `failed`；视觉和非视觉未解决目标均为 0。部分 PDF 页原生文字层包含完整表格，而 MinerU 结果只剩页码，证明主要风险并不只是复杂图片。

原始实验快照为：

```text
├─ final_report.json
└─ <document_id>/
   ├─ parsed_document.json

```

所有 9 个复核证据都已复制到此目录，不依赖之前的实验运行。`logs` 默认不提交 Git。

## 5. 已知限制

1. PDF 确定性补回目前保存页级原生全文和页码，不重建被 MinerU 漏掉表格的精确行列几何；切块时必须把它视为补充证据，避免与 MinerU 内容重复；
2. 最大的 Excel 统一文档约 12.27 MB，结构化切块必须按工作表和行区间流式处理，不能把整表摊平成一个文本块；
3. `openpyxl` 对部分 DrawingML 和外部图表数据支持不完整，图表视觉语义仍以 MinerU 和精确多模态复核为准；
4. PDF 原生文字层可能存在数字拆分，因此它是校验和修复证据，不等同于人工标注真值；
5. 扫描 PDF 没有原生文字层时，还需要视觉区域完整性指标；
6. HTML 目前只有受控样本，需要补真实网页存档；
7. 当前 Streamlit 上传入口仍使用旧 TXT 流程，等切块稳定后再切换。

## 6. 下一节点

人工确认节点 3 后进入节点 4：结构化切块与证据映射。切块需要分别处理标题层级、跨页段落、PDF 补充证据、表格行区间、公式和图表语义，并避免 MinerU 内容与原生修复内容重复。

所有切块方案必须使用现有评测集比较召回率、上下文完整性、重复率、块大小分布和成本，之后才进入 Chroma 与 Qdrant 对比。

## 怎么写、为什么这样写

本次从平铺规则改为 Markdown 的任务与输入、依据证据作答、引用与输出、完整示例四部分。标题本身也是模型输入，不是给维护者的额外说明。

核心仍是“问题＋本次证据→有依据的回答”，不是堆叠专家角色。证据和问题由用户消息输入，规则和虚构示例保留在系统消息；模板加载器只替换一次变量，示例 JSON 不变成模板变量。历史仅用于理解指代，不升级为本次事实。

新增四个完整的证据 JSON—问题—回答示例，分别展示缺少单位的计算、内部冲突、部分可答及空值、目标资料未提供。示例不用评测题的实体与数值，明确标记为示例而非事实证据。计算题即使只给差额，也要求明确写出“原文未注明单位”。

写法借鉴此前核对的 [Anthropic 官方提示词指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)的清晰指令和完整示例，以及 [OpenAI Cookbook](https://developers.openai.com/cookbook/examples/gpt4-1_prompting_guide)的任务、规则、输出和示例分区。它们提供编写方法，不证明某种格式一定对千问最好。借鉴 [DSPy](https://dspy.ai/3.2.0/learn/optimization/optimizers/)用数据检验修改的思路，本次没有安装优化框架或自动搜索提示词。

```powershell
.venv\Scripts\python.exe scripts/run_node7_prompt_ab.py --baseline-report storage/evaluations/zh_public_minibench_v0.1/reports/node7_prompt_ab_64fee8b1fec7.json
```

本轮使用原14题，每题旧、新各一次，共28次真实调用。固定原检索证据及顺序、用户模板、独立会话、`qwen3.8-max`、关闭思考、800输出Token上限；实验禁用备用切换，不改变应用配置。不额外调用嵌入、重排或模型裁判。旧版答案也是本轮重新调用，不是复制上轮结果。

所有14题都已被查看，均属于开发回归题，不再把配置中沿用的 `same_corpus_validation` 标签解释成独立验证集。本轮只隔离回答环节，不重新召回，不等于端到端验收。

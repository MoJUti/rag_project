## 2. 已跑通的功能

- 读取已有新旧会话，显示完整原始对话；不把内部摘要显示成用户消息。
- 新建会话；默认GLM/low，可在发送前显式选择千问，千问关闭思考。不自动切换其他模型或在部分正文后接另一模型。
- 通过SSE返回准备进度、证据、正文片段、最终统计或错误，浏览器不直接持有模型密钥。
- 中文Markdown、表格、代码、来源引用；点击当前回答的S编号打开该回答对应证据，不把旧回答的同名编号关联到新证据。
- 右侧流程查看：实际检索查询、阶段耗时、证据原文与位置、实际模型和接口用量、历史Token统计。
- 同一会话同时只接受一个问答请求，重复并发返回409；不同会话分别存档。
- 失败保留可见的部分输出并标“未完成”，不把提前断流当作成功，不自动重复付费请求。

页面提供“文档管理接入中”的禁用提示，不假装文档上传、切块预览和策略选择已经可用。当前也未提供新版置顶、删除、改名等会话操作。

## 3. 前后端如何分工

| 文件 | 职责 |
| --- | --- |
| `api/main.py` | 本地HTTP接口、会话读写、供应商选择、并发保护、SSE和静态页面 |
| `frontend/src/App.tsx` | 三栏工作台、会话切换、输入、流式显示、引用定位和流程面板 |
| `frontend/src/api.ts` | HTTP客户端、UTF8流式解码、完整SSE事件拼接与异常判定 |
| `generation/observability.py` | 复用逐请求追踪，增加准备结果通知，不重复检索 |
| `generation/rag_service.py` | 原来的回答与检索链，无另造一套RAG |
| `scripts/start_web.ps1` | 构建React，再启动只监听127.0.0.1的统一服务 |

构建后FastAPI直接提供 `frontend/dist`。浏览器只用一个地址，避免开发时两个本地端口相互不可达。Node只在开发和构建阶段需要，运行已构建版本不需要另开Vite进程。

### API约定

| 接口 | 用途 |
| --- | --- |
| `GET /api/health` | 廉价健康检查，不初始化模型 |
| `GET /api/config` | 白名单配置、供应商名称与是否已配置，不返回密钥 |
| `GET /api/sessions` | 读取会话列表 |
| `POST /api/sessions` | 新建空会话，不调用模型 |
| `GET /api/sessions/{id}/messages` | 读取完整原始问答 |
| `POST /api/sessions/{id}/chat` | 接受query及可选provider，SSE回答 |

SSE顺序为start→prepared→多个token→done；失败终结为error，不伪装成done。心跳是注释行。前端兼容任意字节分包、中文被切在中间、CRLF以及多事件同包；未收到done/error就断开时明确报错。

生成在线程中运行，主接口持续发送事件；客户端断开时设置停止标记，等待模型下一次返回片段后退出，不能承诺立即中止供应商计费。会话锁直到实际工作结束才释放，避免另一个请求在断开后马上改写相同历史。

## 4. 模型与安全约定

新版 `API_CHAT_PROVIDER=zhipu`，使用已有 `ZHIPU_CHAT_MODEL`、`ZHIPU_BASE_URL` 和本地 `ZHIPU_API_KEY`。千问复用已有型号、地址和密钥。旧Streamlit模型池配置未改，以免迁移时暗中影响对照入口。

只监听本机，检查Host和Origin，不开放跨站CORS。错误输出对已知密钥和常见sk格式做遮蔽；前端构建不嵌入环境密钥。Markdown不启用原始HTML执行，源码及资源随项目本地构建，不依赖外部字体。

**这是本机单用户版本，没有账户、租户隔离或对公网鉴权，不能直接以0.0.0.0暴露到局域网或公网。** 会话之间不混用证据不等于实现了多租户权限体系。

### 阅读宽度与输入区联动

- 移除“最近对话”后的数量；模型菜单改用统一的线条箭头，展开时向上翻转。
- 去掉输入框右下角原生缩放角标，输入高度随内容自动增长，上限为180像素且不超过视口高度的四分之一，超出内容在输入框内滚动。
- 正文左右各有一条靠近时显示的拖拽线。拖动任意一侧，阅读区域保持居中；正文和输入框共用 `--reading-width`，不再分别设置不同的最大宽度。
- 默认阅读宽度960像素，桌面最小560、最大1280像素；同时不超过主栏可用宽度减112像素。窄屏自动缩窄，不因桌面最小值产生横向溢出；手机布局隐藏拖拽热区。
- `ResizeObserver` 跟踪主栏宽度，因此窗口缩放和流程栏开关都会重新限制有效宽度。拖动使用指针捕获，支持取消；双击恢复默认宽度，键盘方向键微调、Home/End到达上下限。本轮不把宽度写入会话或数据库，刷新恢复默认。
- 前端12项测试通过，覆盖双侧拖动方向、上下限、结束拖动、重置、窗口缩窄、共享宽度规则，以及原有模型切换/历史/流式回答；类型检查和生产构建通过。测试环境不能替代真实浏览器的鼠标悬停和实际几何验收。

拖拽线细化：最大宽度保持用户截图所示的现有上限，不继续扩大；左右线条向外移，距正文边缘约26像素，热区仍可拖拽。线条宽度2像素，淡绿中心向上下两端渐隐，悬停时再淡入。加宽主栏边缘保留区，确保拉到最大也不会挤到滚动条。补充留白及渐变样式回归检查。

# 节点8：同题回答质量与耗时对照

测试日期：2026-10-16。使用已配置的 `glm-5.3-flash`、low 思考档。未切换生产默认预算，未启用跨会话记忆。

后续决定：测试结束后用户确认暂用32K / 4K，已设为默认；详见[当前默认策略](08-记忆与会话压缩.md#10-当前默认策略32k--4k2026-10-16)。以下保留测试当时的方法与结论。

## 1. 本次测试什么

复用上一轮48轮合成会话生成的七组固定上下文，不重新摘要，不检索知识库。每组回答完全相同的问题三次，合计21次真实请求，全部完成：

> 请列出 P001、P024、P048 各自已确认的预算（元）、交付日期，以及是否禁止将资料外发。

三个资料组分别处于早期、中期、近期。每组需要回答预算、日期、禁止事项三个事实，共九个事实。答案要求统一JSON格式，逐字段严格比较，不把出现编号或关键词当作答对。

三轮顺序分别为正序、倒序、旋转，顺序请求，不并发。复用同一份摘要，但每次问答独立发起；不把上一次答案加入下一次请求。历史和摘要作为带角色标签的数据输入，不授予历史摘要系统指令权限。问答提示词位于 `prompts/memory/budget_answer_probe.md`。

时间单位为秒，每组仅三次，表中使用中位数，不估计P95。K为本地估算Token预算，并非实际填满的接口Token数；摘要数值为上限，不是实际长度。

旧配置不是正常摘要基线：上一轮模型返回1698字符，超过1500字符上限，摘要未被接受。本次复用的是降级后的近期两轮上下文。三次均仅答对近期P048的三个事实，早期、中期六个字段返回null，没有编造。不能据此声称“所有4K配置都记不住”。

六组候选共18次都答对九个事实，但不等于覆盖真实场景的100%准确率。这是同一道题的重复结果，不是18道独立题。

## 3. 时间怎么算，哪些不包含

- 开始出字：客户端开始调用至首次收到非空正文，包含连接、服务端等待、输入处理及思考，受客户端流式缓冲影响，不是服务端精确首Token时间。
- 完整答完：从开始调用至正文流迭代结束，包含上述首字等待。
- 不含：本次调用前的历史读取和提示词组装、此前摘要生成、知识库检索、重排、前端渲染。因此不是整个生产RAG流程的端到端耗时。
- 所有请求均设置输出上限800 Token、low思考；供应商返回的缓存命中Token均为0。思考Token实际在0–71之间变化，正文长短也不完全一致。
- 每次调用使用独立连接；网络和平台负载未控制。32K/2K有一次耗时6.85秒，保留原始数据，不删除离群值。不能把全部时间差归因于历史预算。

## 4. 当前可以得出什么

本次简单同题中，增加到64K没有带来可见的正确性提升，却增加了输入量和等待时间；16K已足够回答这道题。32K/2K仍可作为后续复杂场景的折中候选，但尚不能叫“最优”。4K摘要上限本轮也没有体现优势，上一轮所有实际摘要均未达到2K。

这一合成历史包含大量重复流程文字，预算和日期存在规律，模型可依据摘要中的明确规则计算。因此它适合做容量、接口和初步延迟对照，不能证明真实多轮记忆可靠。下一步仍需不规则事实、用户更正、否定条件、遗忘请求、跨主题以及知识库问答结合的测试。暂不根据此表改默认值。

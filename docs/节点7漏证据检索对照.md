# 节点7漏证据检索对照

日期：2026-10-15。范围：检索实验，不修改生产默认配置、不修改回答提示词、不新增模型请求。

## 1. 本轮结论

混合分词配合现有邻接扩展，在本轮补齐了8道已知漏证据题中6道的诊断要求。剩余两道的关键证据已经进入候选池，但没有进入最终六块，需要继续验证排序策略。

这不是“回答正确率达到75%”。8题是看过结果后选择的问题子集，而且其中两题的诊断要求只覆盖此前缺失的一侧；回答模型本轮没有运行。新增19道可回答题另按原标注检查，混合分词前六块已达到19/19证据完整。

## 2. 对照是怎么实现的

入口：`scripts/compare_node7_retrieval_gaps.py`。

```powershell
.venv\Scripts\python.exe -X utf8 scripts/compare_node7_retrieval_gaps.py
```

固定条件：

- 使用正式本地Chroma中的2,881个切块，以及缓存的 `text-embedding-v4 / 2048` 问题向量。缺少缓存时明确报错，不在线生成。
- 校验切块ID、正文、来源与冻结语料完全一致。诊断附表同时绑定原端到端报告及其内容指纹。
- 两路各取20条，等权RRF融合，常数60，取前6块。所有分词策略使用同题的**同一次向量召回结果**。
- `char` 是旧逐字分词；`mixed` 保留中文单字和相邻双字，将英文、数字组合尽量作为整体词元。不是更换嵌入模型。
- 邻接扩展沿用既有实现：半径1、额外预算2,000估算Token，同文档、章节约束、同表约束、去重且保留种子。不是整篇文档回填。
- 对74道可回答题运行回归，4道拒答题不混入召回率。标注只参与事后评分，不参与检索选择。

每题保存种子/扩展切块ID、实际块数、估算Token、诊断命中项。8题另记录各证据在候选池中的位置，区分“没召回”和“召回后没入选”。

## 5. 重排测了多少，没测什么

本轮没有新增重排API请求。复用缓存必须同时满足：

1. 缓存绑定相同问题和语料指纹。
2. 当前查询与缓存查询一致，有序输入候选逐一一致。
3. 缓存保存完整、无重复的重排排列，而不是只有前十名。

本轮新增19题均满足条件：混合分词＋历史千问重排前6块为19/19证据完整，与不重排相同；平均上下文约2,914估算Token，高于不重排的2,685。不能由此推断所有问题都不需要重排。

旧55题缓存缺少完整输入候选，未纳入严格重排对照。因此**不能声称已经验证重排能解决剩下两道旧题**。需要新调用时先确认，不用其他题的缓存顶替，也不静默调用回答或重排模型。

## 6. 排名波动与实验边界

复跑发现少数查询的排名未完全复现历史结果。正式记录中为 `omni-05-01` 和 `wb-37-01-02`；此前一次复跑还出现其他题的变化。根因尚未单独定位，不能直接认定为数据库缺陷。

为避免混淆变量，本轮每题向量结果只读取一次，供所有分词策略共用；报告保存该次完整向量候选与历史差异。近似召回和同分排序稳定性仍需后续检查。邻接策略依赖种子，所以个别引文分数和Token也会随种子波动；不能承诺重复运行每个数值都不变。

本轮各次运行中“混合分词补齐4题、加邻接补齐6题”的观察保持一致，但这不是多随机种子稳健性评测。所有题目都是已见开发/回归题，不是独立盲测。

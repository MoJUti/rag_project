## 2. 第一批界面能看什么

聊天页保留现有气泡、会话列表与流式输出，增加两个折叠区域：

### 当前运行配置

只读展示向量库及集合、嵌入模型和维度、召回和分词策略、候选数量、最终块数、重排、查询消歧、证据扩展、配置首选回答模型、备用策略和历史预算。

“配置首选模型”不等于实际已调用模型，不能据此推断某次回答一定由千问或GLM生成。页面不列密钥、鉴权头或完整环境变量，也不在本批提供策略切换按钮。

### 最近一次问答流程

显示当前浏览器中该会话最近一次请求的完成/失败/中断状态、收到首个文本片段的时间和整次消费流的耗时，分四个标签页：

1. 检索问题：原始提问、实际查询、消歧动作、澄清文本和历史锚点。
2. 阶段耗时：查询消歧、查询处理、候选召回、融合、重排及最终证据的已有阶段记录；未执行的阶段不凭空补上。
3. 证据原文：选择进入回答的证据，查看切块ID、文档ID、来源位置和原文。使用纯文本渲染原文，不执行文档中的HTML或指令。进入证据不代表一定被模型引用或正确理解。
4. 模型与历史：实际捕获的模型名称、结束原因和接口Token；历史消息数、估算Token及是否带摘要。默认不展开完整对话和摘要正文。

没有流程快照的旧聊天不伪造数据，也不会为补一个面板重新运行检索或模型。

## 3. 核心实现：观察同一次调用，不复制业务链

`generation/rag_service.py` 在检索准备完成时发送 `rag_prepared` 自定义回调事件，内容来自**本次实际结果**：查询消歧决策、阶段记录、证据和历史统计。普通 `chain.stream` 调用仍然返回原来的字符串流。

`generation/observability.py` 为每个请求新建 `RequestTraceRecorder`，合并到该请求的回调配置，不改原传入配置，不在服务对象或模块全局保存最后一个用户的资料。模型元数据仅收集白名单字段；异常记录类型，不把第三方错误中的潜在鉴权内容复制进流程记录。

`stream_with_trace` 只调用一次原回答链，逐片段原样转发，在结束、抛错或关闭生成器时记录最终状态。异常仍向原界面抛出，不吞错、不改变模型池、不重跑检索。失败发生在检索完成后时保留已获得证据；准备未完成时明确写“尚未采集”，不伪装成知识库无资料。

`app/trace_panel.py` 只渲染已采集数据，不初始化模型或检索。`app/streamlit_chat.py` 用浏览器 `session_state` 按会话ID保存最近一次结果；切换会话读取对应结果，删除会话时同时移除其流程快照。刷新仅重绘，不产生新的付费请求。

## 4. 数据与指标的边界

- 快照仅保留在当前Streamlit浏览器会话内，不写入聊天正文、logs或正式知识库，也不承诺服务重启后仍可回看。持久化审计记录需要下一阶段单独讨论。
- 首段正文时间是客户端收到非空字符串的时间，不是服务端精确首Token时间；总耗时直到消费者读完整个流，可能包含Streamlit处理输出的时间，不等于纯模型生成耗时。
- 阶段表是检索管线计时，不能将其简单求和当作整次问答耗时；历史读取、摘要及生成等未全部单独拆时。
- 当前hybrid检索内部已经融合向量和BM25候选。表中“候选召回（管线输出）”不代表已经展示两路各自的完整候选和分数，后续再接。
- 模型Token只展示接口实际返回值，缺失为空，不填0。非回答模型调用暂统一标“其他”，不承诺已完整捕获每次摘要的用量或计算出整链费用。
- 目前展示的是提供给回答链的历史数量、估算Token和摘要存在标志，不是摘要语义质量认证；摘要覆盖游标和持久化降级原因尚未做完整界面展示。
- 顶部是当前进程配置；实际运行中的服务需要加载新版代码后才有新事件。建议重启已有Streamlit服务，不把旧服务实例的缺事件视为业务无结果。

# MinerU API 全格式基线测试（2026-09-28）

## 1. 测试目的

验证 MinerU v4 精准解析 API 在当前中文多格式评测资料上的：

- 网络、Token、签名上传、轮询和 ZIP 下载链路；
- PDF、图片、DOCX、PPTX、XLSX 的格式支持；
- `MinerU-HTML` 独立模型；
- 文本、页面、幻灯片、单元格和关键证据的基础保真度；
- `vlm` 失败后切换 `pipeline` 是否能够自动恢复。

本报告是节点 3 开发前的基线实验，不代表解析质量门控已经实现。

公开评测资料共 55 份：

|---|---|---:|

## 4. 分格式结果

### 4.1 DOCX

使用 OOXML 原生段落作为独立参考，6 份 DOCX 的归一化段落完全匹配率为：

```text
87.0% ～ 100.0%
```

最低样本不等于丢失 13% 正文，差异还包含文本框顺序、重复段落、表格拼接与格式变化。正式质量门控需要按段落、表格和文本框分别判断。

### 4.2 PPTX

4 份 PPTX 的幻灯片数量全部一致：

```text
34/34
28/28
16/16
16/16
```

OOXML 原生文本与 MinerU 结果的归一化完全匹配率为：

```text
98.9% ～ 100.0%
```

该结果说明当前样本的幻灯片文字覆盖很好，但尚未验证图表数据、元素遮挡和复杂动画顺序。

### 4.3 XLSX

使用 Excel 的缓存显示值进行比较后，7 份工作簿的可验证单元格覆盖率为：

```text
99.98% ～ 100.0%
```

初次用公式字符串与 MinerU 显示值比较时产生了低分误报。例如一个可视化工作簿含 38,723 个公式，其中只有 259 个保存了缓存结果。MinerU 输出面向可见内容，不保留大量原始公式表达式。

结论：

- 单元格展示值恢复很好；
- 公式表达式不能依赖 MinerU；
- 节点 3 必须用原生 XLSX 提取补充 `formula` 字段；
- 表格评测不能只使用整段证据字符串匹配。

### 4.4 PDF

两份年度报告的页面数量完全一致：

```text
175/175
161/161
```

相对于 PDF 原生文字层，四字符片段覆盖率分别为：

```text
78.30%
80.99%
```

MinerU Markdown 的文字量约为原生提取的两倍，主要因为 MinerU 额外恢复了表格结构，而原生 PDF 提取对表格和分栏处理较弱。现有正式问题的 PDF 证据三字片段平均覆盖率为 83.02%，5 个问题中 4 个达到 80% 以上。

进一步对原生文字层与 MinerU 结果中的关键数字做归一化核对：

```text
关键数字覆盖：2897/2909（99.59%）
确认遗漏：12 个唯一数字，分布在 2 份 PDF
```

遗漏比例很低，但存在语义影响较大的“静默遗漏”：

- 某行业报告的“2024 年空调产销规模及增速”图表只保留了标题和图片引用，`19508 万台`、`18977 万台`、`19.5%`、`20.9%`、`9652 万台`、`9326 万台`、`6.6%`、`40.4%` 等图表数字没有进入 Markdown 正文；
- 某年度报告原文中的“2024 年，全社会用电量 98521 亿千瓦时”被解析成“年，全社会用电量 亿千瓦时”；
- 同一段中的“未来五年计划投资规模约为 3,500 亿美元”被解析成“约为 亿美元”。

这些文件的 API 状态仍为 `done`，页面数量也完整，说明“任务成功”和“页数完整”不能证明关键事实完整。现有 PDF 问题集没有询问上述遗漏数字，因此仅运行现有问答评测也无法发现这些问题。

因此 PDF 不能仅凭 API 状态、页数或整体文本相似度判定成功，需要按页比较并单独评价表格、图表、标题、阅读顺序和关键数字。

### 4.4.1 非图片格式关键数字核对

| 格式 | 原生参考中的唯一关键数字 | MinerU 保留 | 覆盖率 |
|---|---:|---:|---:|
| DOCX | 80 | 80 | 100% |
| PPTX | 22 | 22 | 100% |
| XLSX（缓存显示值） | 1280 | 1280 | 100% |
| PDF | 2909 | 2897 | 99.59% |

这里的“关键数字”采用去除千位分隔符后的唯一数字集合，只适合作为完整性告警，不代表完整的语义正确率。它能够发现整体文本相似度容易掩盖的金额、比例、产销量等缺失。

### 4.5 图片与 OCR

12 张 OmniDocBench 图片全部完成解析。与标注文本比较：

```text
平均文本顺序相似度：71.26%
平均三字片段覆盖率：81.79%
```

人工检查发现三个典型问题：

1. `omnidoc-02`：大量手写数学内容出现错字和公式识别错误，例如“因数”被识别为“内数”。
2. `omnidoc-05`：竖排关键文字“山风蛊”和“变卦火泽睽”完全遗漏，导致对应问题不可回答。
3. `omnidoc-11`：页面顶部的 B、C 两个选项遗漏，主体推导过程基本保留。

`omnidoc-09` 的自动文本分数较低，但人工检查确认表格标题及主要内容完整，低分主要来自标注表示与 HTML 表格表示差异。这说明解析评测必须结合结构指标，不能只用纯文本编辑距离。

### 4.6 HTML

受控中文 HTML 使用 `MinerU-HTML` 解析成功：

- 标题、正文、列表、数字、否定句和表格全部保留；
- 导航栏和页脚被正确排除；
- `full.md` 为干净 Markdown；
- `main.html` 保留正文 DOM 结构。

当前 HTML 只验证了受控样本，仍需补充真实网页存档、乱码编码和复杂嵌套表格。

### 4.7 Markdown

24/24 份 Markdown 文件能够本地读取，0 个空文件。Markdown 不需要上传 MinerU。

## 5. `pipeline` 降级复测

对 `omnidoc-02`、`omnidoc-05`、`omnidoc-11` 三张问题图片使用 `pipeline + OCR` 重试。

| 样本 | VLM 三字片段覆盖 | Pipeline 三字片段覆盖 | 结论 |
|---|---:|---:|---|
| omnidoc-02 | 65.59% | 51.82% | Pipeline 更差 |
| omnidoc-05 | 80.06% | 79.45% | 仍遗漏竖排关键文字 |
| omnidoc-11 | 64.67% | 72.46% | 局部提高，但仍遗漏 B、C 选项 |

结论：切换 `pipeline` 不是可靠的自动修复方案。对于手写、竖排和页面边缘内容，需要：

- 元素级质量检测；
- 局部裁剪后重新 OCR；
- 第三解析器或视觉模型交叉验证；
- 无法确认时进入人工检查队列。

## 6. 评测方法限制

“标准答案是否原样出现在解析文本中”不能直接代表解析准确率。55 个问题中只有 28 个答案原样出现，主要原因包括：

- 表格问题需要计算或聚合；
- 答案由多个单元格组合；
- 数字格式和单位发生规范化；
- Markdown、HTML 表格和原始证据的序列化方式不同；
- 公式 LaTeX 表示不同。

因此节点 3 的质量门控必须按格式使用不同指标：

- PDF：页级覆盖、阅读顺序、表格和关键事实；
- DOCX/PPTX：原生段落、文本框和页面/幻灯片结构；
- XLSX：单元格坐标、缓存值、公式和合并单元格；
- 图片：OCR、布局、公式及关键区域；
- HTML：正文 DOM、表格、链接和噪声移除。

此外，现有问答评测集需要补充解析器专项断言。问答覆盖到的事实全部正确，并不代表未被提问的数字和图表也被正确解析。

## 7. 对节点 3 的直接结论

MinerU 可以作为主解析器，但不能把 `state=done` 直接视为可入库。节点 3 至少需要实现：

1. 完整 ZIP 持久化；
2. 格式专属的原生证据提取；
3. 页面、幻灯片、工作表和关键区域完整性检查；
4. Excel 公式的原生补充；
5. 图片的手写、竖排和边缘遗漏检测；
6. 元素级 `success/partial/failed`；
7. 自动重试后仍失败的人工复核入口；
8. 不合格文档禁止进入切块和向量库。

非图片文档的建议解析策略为：

- DOCX、PPTX：MinerU 作为主输出，OOXML 原生提取用于完整性校验和缺失补全；
- XLSX：`openpyxl` 原生结构、坐标、显示值和公式作为主数据，MinerU 结果用于可读文本与视觉化表格表示；
- PDF：MinerU 作为结构化主输出，同时用 PyMuPDF 或 pypdf 提取原生文字层，执行页级关键数字对账；图表区域只有图片引用而无结构化数据时标记为 `partial`；
- HTML：使用 `MinerU-HTML`，但在真实网页样本补充前不宣称已经完成生产级验证；
- Markdown：本地解析，不经过 MinerU。

## 8. 千问多模态异常页复核实验

使用已配置的百炼 OpenAI 兼容接口：

```text
https://maas.qianwenaiapi.com/compatible-mode/v1
```

接口鉴权和模型列表查询成功。账号当前可见 `qwen3.8-max`、`qwen3.8-flash`、`qwen3-vl-plus`、`qwen-vl-ocr` 等模型。本次选择两个 MinerU 已确认遗漏的真实 PDF 样本进行盲检，提示词只描述需要提取的字段，不提供标准答案：

1. 跨页正文：全社会用电量、同比增长率、未来五年投资规模等数字；
2. 图表：2024 年空调生产、销售、内销和出口规模及同比。

### 8.1 对比结果

| 模型与模式 | 跨页正文 | 空调图表 | 耗时 | 总 Token |
|---|---|---|---:|---:|
| `qwen3.8-max`，思考开启 | 全部正确 | 全部正确 | 48.50s / 110.56s | 8592 / 12204 |
| `qwen3.8-max`，思考关闭 | 全部正确 | 全部正确 | 10.06s / 10.89s | 5619 / 5692 |
| `qwen3-vl-plus` | 错把市场交易电量 `61795.7` 当成全社会用电量，遗漏 `98521` 和 `6.8%` | 全部正确 | 15.19s / 13.18s | 5704 / 5621 |

`qwen3.8-max` 在关闭思考后仍准确恢复：

- `98521 亿千瓦时`、同比增长 `6.8%`；
- 未来五年计划投资约 `3,500 亿美元`；
- 生产 `19508 万台 / 19.5%`；
- 销售 `18977 万台 / 20.9%`；
- 内销 `9652 万台 / 6.6%`；
- 出口 `9326 万台 / 40.4%`。

### 8.2 当前决策

- 不引入 PaddleOCR-VL；
- MinerU 继续负责全量主解析；
- 异常页面渲染为高清图片后，直接调用千问多模态模型；
- 当前默认复核模型选择 `qwen3.8-max`，结构化提取默认关闭思考；
- `qwen3-vl-plus` 可以作为低延迟对照模型，但不能仅凭本次图表成功就替代跨页复核；
- 千问结果必须保留原始页面、页码和原文证据，并与 MinerU 或 PDF 原生文字层进行一致性检查。

当前仅有两个针对性样本，这一结果足以证明千问能够修复已发现的 MinerU 漏项，但不足以证明所有文档类型都应固定使用同一个模型。后续应把这些样本纳入解析器回归集，再扩大跨页、表格、图表和模糊扫描件测试。

本次基线证明 API 和大部分常规格式可用，同时也实证了质量门控不是可选功能。

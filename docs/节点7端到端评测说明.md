# 节点7端到端评测说明

## 这一步做什么

前面的提示词对比固定检索证据，只检查“给定资料后怎么回答”。本轮让问题进入正式回答链，实际执行当前召回、融合、证据编号、模型回答和来源追加，检查整条链是否能一起工作。

不修改提示词、不更换模型、不调整检索参数，也不把标准答案或指定原文塞进回答上下文。评测代码通过子类观察正式链中的检索结果；每题只检索一次，模型看到的就是记录下来的那份证据。

入口为 `scripts/run_node7_end_to_end.py`，新增测试在 `test/test_node7_end_to_end.py`。业务问答链本身不因评测改变。

## 题目与配置

合并55道原检索题和23道新增题，共78题，包含74道可回答题、4道资料不足题。不加入提示词对比中的4道人造边界题，避免混淆公开资料问答与合成输入测试。

这些资料和题目已用于先前检索实验，部分题还参与提示词优化；本轮是同库开发回归基线，不是外部盲测。原文件中的 `dev`、`holdout-public` 等历史标签不改变这一事实。

本次使用当前配置：

| 环节 | 配置 |
|---|---|
| 向量库 | Chroma本地模式，`rag_text_embedding_v4_2048` |
| 文档向量 | `text-embedding-v4` / 2048维，已有2,881块 |
| 问题向量 | 原题的已校验缓存，不新增API调用 |
| 召回 | 向量20条＋字符级BM25 20条，RRF常数60 |
| 最终证据 | 6块 |
| 重排 / 邻接扩展 | 均关闭 |
| 回答 | `qwen3.8-max`，关闭思考，输出上限800Token |
| 智谱备用 | 仅本轮实验禁用，应用配置不改 |
| 会话 | 每题独立内存历史，不写用户聊天记录 |

这是当前应用配置的一次基线，不等于先前节点6的 `hybrid_mixed` 参数组；不把不同分词和不同召回方式的数字直接当作模型提升。

缓存复用的是问题向量，不是旧召回结果或旧答案。检索、融合和回答都重新执行；因此当前耗时不包括在线问题嵌入请求，不能当作用户实际完整等待时间。

## 怎么保证结果可追溯

1. 核对新增题冻结指纹，以及全部问题向量的文本、模型、维度。
2. 核对正式库和切块目录的ID、正文、文档ID及数量，防止用错库。
3. 记录题目、问题向量和切块指纹、实际提示词正文、当前检索参数、模型参数和相关代码指纹。
4. 每题保存实际证据及来源位置、检索阶段记录、原始和展示答案、结束原因、引用编号检查、模型信息和用量。
5. 完成一题原子保存一次，同一输入可续跑；失败保留错误和已取得的检索结果，不静默覆盖，不自动重复付费。

```powershell
# 全部78题；中断后用相同命令续跑。
.venv\Scripts\python.exe scripts/run_node7_end_to_end.py

# 先运行前3题；使用同一身份缓存，之后可继续跑其余题。
.venv\Scripts\python.exe scripts/run_node7_end_to_end.py --limit 3
```

程序在本地 `storage/evaluations/zh_public_minibench_v0.1/reports/` 生成带指纹的JSON，而非日志目录。提示词或配置改变后会产生新的文件，不覆盖旧成绩。不要同时启动两个相同实验进程写同一文件。

## 哪些指标能自动算

运行完成数、失败数、模型结束状态、平台返回Token、未知引用编号、无引用答案数，以及已有标注对应的召回指标。拒答题只记录指定来源是否进入上下文，不能用它计算“拒答正确率”。

两套题沿用原本已使用的证据评分方式，因此**分别汇总**：

- 原55题：文档Recall、MRR、nDCG；同文档内单切块的字符片段覆盖率达到0.75时，视为该证据命中。该规则允许排版/OCR差异，但也可能出现语义不等价的相似文本，不是事实核验。
- 新增19道可答题：按文档等价组评分；文字证据及必要上下文规范化后匹配，图像区域采用0.9片段覆盖阈值，允许同来源多块共同支持。

命中文档不等于找到了答案，找到证据也不等于模型答对。两套证据指标口径不同，不合成一个貌似精确的总体证据召回率。

## 哪些必须对照原文复核

是否正确、是否答全、是否合理拒答、是否混淆实体/时间/单位、引用是否支持相邻断言。这些不能由引用编号存在、字符串相等或请求成功推导。

每个新答案默认标记 `awaiting_source_based_review`，自动摘要标记 `semantic_review: pending`。在逐项复核完成前不输出全量回答正确率、引用精确率或覆盖率。助手复核也不等于独立人类评审。

发现问题时沿着证据快照定位：原文有、入库块没有，优先看解析/切块；库里有、最终上下文没有，优先看召回/融合/截断；上下文已有而答案错，优先看生成规则或模型。原始标注本身有歧义时单列标注问题，不自动把参考答案判为绝对正确，也不偷偷改标准答案。

本轮真实运行及发现的问题见[节点7端到端首轮结果](节点7端到端首轮结果.md)。节点7只有完成回答与引用的语义复核和问题处理后才能验收，不因脚本跑完就自动转入节点8。
